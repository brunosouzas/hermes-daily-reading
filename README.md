# hermes-daily-reading

A daily reading digest for [Hermes Agent](https://github.com/NousResearch/hermes-agent). Once a day it reads your RSS and Atom feeds, groups the same story when several feeds carry it, and ranks what is new by the themes you care about. It writes a short summary in your language (an introduction plus one paragraph per item) and reads it aloud with the TTS voice you already use in Hermes. The result shows up on a **Daily reading** page in Hermes Desktop, where you can mark items read, save one as a note fragment, or turn it into an article idea.

It runs as an ordinary Hermes cron job, so the digest is ready at 07:00 even when Desktop is closed.

License: [MIT](LICENSE). Requires Hermes 0.22.2 or later. No Python packages to install: the standard library plus the PyYAML that Hermes ships.

## How it compares

Four catalog plugins come close. None of them does this job, which is why this one exists:

| Plugin | What it is | Why it is not this |
|---|---|---|
| morning-briefing | A skill that has the agent write scripts each run and print a PDF | No feed list, no audio, no page; the pipeline is regenerated by the model every day |
| hermes-rss | A three-column reader inside Desktop | Library lives in the Desktop window's storage; nothing runs with Desktop closed |
| rss-reader | A fork of hermes-rss with a backend and an agent tool | Same storage; its tool needs the Desktop window to answer |
| hermes-newswire | A headline ticker and news page | A ticker: no ranking by theme, no summary, no audio |

What this plugin adds: a short audio digest (about 5 minutes by default), ranking by your own themes with weights, duplicates removed across feeds, and a routine that works headless.

The feed-fetching guard (address checks, redirects, size and time limits) and the HTML-to-text and date helpers are adapted from [hermes-newswire](https://github.com/tony-simons-aiowa/hermes-newswire) by Tony Simons (MIT); the notice is kept in `dr_fetch.py` and `dr_parse.py`.

## Install

```bash
hermes plugins install brunosouzas/hermes-daily-reading
hermes plugins enable daily-reading
```

The Desktop page ships disabled, like every plugin's desktop half: turn it on in **Capabilities → Plugins**.

## Feeds

Your feeds live in one YAML file, `$HERMES_HOME/daily-reading/feeds.yaml` (change it with the `feeds_file` setting):

```yaml
feeds:
  - url: https://martinfowler.com/feed.atom
    theme: software architecture      # optional, shown on the page
  - url: https://blog.cloudflare.com/rss/
    title: Cloudflare                 # optional display name
    paused: true                      # optional: keep it, stop fetching it
```

Only `http` and `https` URLs without a user name or password are accepted. An invalid entry is skipped and reported; the rest of the file still works. Two entries for the same feed (same address after lower-casing the host and dropping the `#fragment`) count once.

Four ways to change it, all with the same checks:

- **The page**: Daily reading → Feeds.
- **The CLI**:

  ```bash
  hermes reading feeds list
  hermes reading feeds add https://example.com/feed.xml --theme "integration"
  hermes reading feeds set https://example.com/feed.xml --theme "architecture" --title "Example"
  hermes reading feeds pause https://example.com/feed.xml
  hermes reading feeds resume https://example.com/feed.xml
  hermes reading feeds remove https://example.com/feed.xml
  ```

- **Asking Hermes** ("add this feed to my daily reading"): the agent uses the `daily_reading_feeds` tool.
- **A text editor.**

Edits made by the plugin rewrite the file, so comments you added by hand are lost. Edits are serialised and written atomically: two edits at the same time both land, and a failed write leaves the old file as it was.

## Running

```bash
hermes reading run            # build today's digest, or report the one already built today
hermes reading run --force    # build it again
hermes reading status         # last digest, item count, failures, feeds
```

One digest per day. A second run the same day reports the existing digest and fetches nothing; `--force` builds a new one and replaces it in one step (readers never see a half-written digest). Only one run happens at a time per profile: a scheduled run waits up to 2 minutes for one already in progress, the page's run button does not wait.

### Scheduling

The plugin adds a **Daily reading** blueprint (default 07:00). Pick it in the Desktop Cron page, or:

```
/blueprint daily-reading:daily time=06:30
```

The job's prompt only asks the agent to call `daily_reading_run`. The ranking and the summary use the model the cron job runs with, through Hermes' own model access, so choose a capable model for the job if your default one is small.

### What a run does

1. Fetches every active feed (up to `max_feeds`, in file order), each with its own time and size limit.
2. Keeps the newest `max_items_per_feed` items per feed and drops items older than `max_age_days`. An item without a date counts as new only on the day it was first seen.
3. Groups the same story across feeds: same link (tracking parameters such as `utm_*`, `fbclid` and `gclid` ignored), same feed id, or the same long title. The first feed in your file wins for the title and the text; all feeds are listed as sources.
4. Skips anything already shown in the last `seen_days` days.
5. Ranks the rest: the model scores each item 0–3 against each theme, and the weighted total decides the order (newest first on a tie). If the model fails or answers badly, keyword matches on the title and text score instead. Without themes, items are just newest first.
6. Keeps `max_items`. With a theme cap (`max_items_per_theme` or a theme's `max_items`), each item counts under its primary theme (the one with the highest score × weight; on a tie, the theme listed first), and a theme takes at most its cap; the items it cannot take wait and fill any slots the other themes leave free, so a day with news on one theme only still gives a full digest. Items that match no theme come after those. The same rule, with a proportional quota per theme, picks the `max_rank_candidates` items the model sees. The digest records how many items the cap left out (`ranking.theme_cap_left_out`). It then asks the model for the summary in `language`, sized to `audio_minutes × words_per_minute` words (or `summary_words`), and sends it to Hermes' `text_to_speech` tool in pieces of at most 1500 characters, split at paragraph breaks (an uncompressed voice such as Kokoro would otherwise pass Hermes' 10 MiB per-file limit). The pieces play in order on the page.
7. Publishes the digest. If the summary or the audio fails, the digest is still published with the items and the failure is reported.

## Settings

Set them in `config.yaml` under `plugins.entries.daily-reading.settings`, or with `hermes config set plugins.entries.daily-reading.settings.<name> <value>`. A missing setting uses its default; a value of the wrong type or out of range uses the default and logs one warning.

| Setting | Default | Range / values | What it does |
|---|---|---|---|
| `feeds_file` | `$HERMES_HOME/daily-reading/feeds.yaml` | path | The feeds file |
| `language` | `en` | language code, e.g. `pt-BR` | Language of the summary and audio |
| `themes` | `[]` | list of `{name, keywords, weight, max_items}` | What to rank by, see below |
| `max_items` | 8 | 1–30 | Items per digest |
| `max_items_per_theme` | 0 (no cap) | 0–30 | Most digest items one theme may take; a theme's own `max_items` overrides it |
| `audio_minutes` | 5 | 1–15 | Target audio length |
| `words_per_minute` | 150 | 80–250 | Speaking rate used to size the summary; tune it to your voice |
| `summary_words` | 0 | 0, or 100–3000 | Fixed summary length; 0 derives it from the audio length |
| `fragments_dir` | empty (off) | folder | Where "save as fragment" writes |
| `ideas` | `{target: none}` | see below | Where "turn into article idea" sends |
| `max_age_days` | 3 | 1–30 | Oldest item considered |
| `seen_days` | 30 | 1–365 | How long a shown item stays hidden |
| `keep_digests` | 7 | 1–90 | Digests (with audio) kept on disk |
| `max_feeds` | 100 | 1–500 | Active feeds fetched per run |
| `max_items_per_feed` | 30 | 1–200 | Newest items read per feed |
| `max_rank_candidates` | 60 | 5–200 | Items sent to the model for ranking |
| `max_excerpt_chars` | 1200 | 200–5000 | Characters of each item sent to the model |
| `fetch_timeout_s` | 15 | 1–60 | Per-feed time limit |
| `max_feed_bytes` | 2 MiB | 64 KiB–10 MiB | Per-feed size limit |
| `user_agent` | `hermes-daily-reading/<version>` | one line, ≤ 300 characters | Sent to feed servers; some sites refuse unknown clients |

Themes, most important first:

```yaml
themes:
  - name: integration architecture
    keywords: [MuleSoft, API-led, event-driven]   # optional; the name is a keyword too
    weight: 3                                    # optional, default 1; 0 turns a theme off
  - name: AI agents
    keywords: [agent, MCP, LLM]
    weight: 2
    max_items: 3                                 # optional, 1-30; overrides max_items_per_theme
```

## The Daily reading page

The page shows the latest digest (or any kept one): the introduction, an audio player, and each item with its paragraph, sources and matched themes. Titles open in your browser only when the link is `http` or `https`. All feed and model text is shown as plain text.

Per item:

- **Mark read / unread.**
- **Save as fragment.** Appends the item (title, link, sources, date, optional note) to `<fragments_dir>/daily-reading-<date>.md`. Saving the same item again does nothing. Off until `fragments_dir` is set.
- **Turn into article idea.** Shows a preview first: title, link, sources, the item's paragraph and where it will go. Nothing happens until you confirm. A preview can be confirmed once, within 10 minutes, and only while the digest and the idea settings are unchanged. If the idea was already sent, or a previous attempt ended without a clear outcome, the preview warns that confirming may create a duplicate.

`ideas` targets:

```yaml
ideas: {target: none}                                  # default: the action is off
ideas: {target: file, file: ~/notes/article-ideas.md}  # appends an entry
ideas:                                                 # runs a program, without a shell
  target: command
  command: [az, boards, work-item, create, --type, Issue, --title, "{title}",
            --description, "{summary}\n\n{url}\n\nSources: {sources}", --fields, System.Tags=artigo]
```

In a command, `{title}`, `{url}`, `{summary}` and `{sources}` are replaced inside each argument and never split into new ones, so text from a feed cannot add arguments or reach a shell. The command gets 30 seconds; its first line of output is shown on the page. Exit code 0 is "sent", any other is "failed", and a timeout is "unknown".

## What it reads, sends and writes

**Reads:** the feeds file; the plugin settings in `config.yaml`; the feeds themselves.

**Sends:**

- To each active feed's server: one HTTP GET (plus redirects, up to 5) with the user agent `hermes-daily-reading/<version>` (or your `user_agent`). No cookies, no proxy. Addresses that resolve to loopback, private, link-local, CGNAT, multicast or reserved ranges are refused, also after a redirect.
- To the model Hermes runs with (your provider): for ranking, the title and up to `max_excerpt_chars` of text of up to `max_rank_candidates` items, plus your theme names and keywords; for the summary, the same fields of the chosen items and the language. Feed text is marked as untrusted data in both requests.
- To Hermes' `text_to_speech` tool: the summary text. Where it goes depends on your TTS provider; a local provider such as Kokoro keeps it on your machine.
- When you confirm an article idea with a `command` target: the item's title, link, paragraph and sources, as arguments to your program.

**Writes**, all under `$HERMES_HOME/daily-reading/` unless you point a setting elsewhere:

- `feeds.yaml` (when you edit feeds through the plugin);
- `digests/<date>/<generation>/digest.json` and the audio files, kept for `keep_digests` days;
- `state.sqlite`: which items were shown and when, when undated items were first seen, read marks, article-idea previews and attempts;
- `run.lock`;
- fragment files in `fragments_dir`, and the ideas file, only when you use those actions.

Logs carry counts, feed URLs and failure reasons, never feed or model text.

## Development

```bash
python3 -m venv .venv && .venv/bin/pip install pytest pyyaml fastapi httpx ruamel.yaml croniter
.venv/bin/python -m pytest -q                                   # Python tests, offline
node --import ./tests/desktop/register.mjs --test tests/desktop/ # page tests, no browser
hermes plugins validate .
```

The feeds under `tests/fixtures/feeds/` were recorded from real sites with `tests/record_feeds.py`; tests never use the network. Two tests use a local Hermes when one is present and skip otherwise: `tests/test_blueprint.py` checks the blueprint with Hermes' own validator (checkout at `~/.hermes/hermes-agent`, or `HERMES_AGENT_DIR`), and `test_unauthenticated_disabled_or_other_profile` mounts Hermes' own dashboard app in Hermes' Python (found under `~/.hermes/installs/`, or `HERMES_PYTHON`) to check that the page's routes need the session token, disappear when the plugin is disabled, and only see their own profile.
